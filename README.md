# 受控采集区的末段损坏恢复（本地防泄露采集区）

原生 Windows、Python 3.12、**仅标准库**实现。输入为虚构设备的封签分段与按设备
签批的容量；公开侧以「最后分段摘要 + 批准代 + 目录承诺」为共同承诺；未完成或权限
被撤销的批次绝不进入公开索引。

## 运行

```bat
python run_tests.py
python -m cage.checker <采集区根目录>
```

## 目录布局

```
cage/
  seal.py    规范信封、SHA256 摘要链、HMAC 封签、zlib 压缩与 pack 分帧
  fsutil.py  原子写；Windows 经 CreateFileW/FlushFileBuffers 做目录级落盘
  ledger.py  每设备追加日志与状态机（approve/revoke/stage/commit/abort/watermark）
  cage.py    采集区核心：签批、暂存去重、三阶段提交、崩溃恢复、公开索引与根承诺
  checker.py 独立检查器（不 import cage/ledger，自带状态机，只认磁盘文件）
  driver.py  流式合成负载（生成器逐段产出，十万段不落地进内存）
tests/
  test_core.py    封签往返/篡改检测/批准代轮换/容量/检查器抓篡改/根承诺
  test_threads.py 双线程 Barrier：撤销抢先、末段摘要不符、目录落盘回执丢失
  test_memory.py  十万段四阶段内存核算（峰值 < 8 MiB）与中断租户隔离
run_tests.py     unittest 发现入口
```

## 封签分段格式（seal.py）

```
MAGIC(4) | 头长(4) | zlib(规范头 JSON) | 载荷长(8) | zlib(载荷) | HMAC-SHA256(32)
```

- 规范头字段：版本、租户、设备、批次、批准代 `g`、序号 `s`、末段标志 `f`、
  上一段摘要 `p`、原始长度 `n`、本段摘要 `digest`、封签 `mac`。
- 摘要链：`digest_i = sha256(digest_{i-1} || zlib载荷_i)`，首段上一摘要为 32 个 0。
- `mac = HMAC-SHA256(设备密钥, 去掉 mac 字段的规范头)`，常量时间比较。
- 同输入产生**逐字节相同**的 frame，重投按段摘要去重；序号/前摘要冲突显式报错。

## 提交协议（cage.py，三阶段）

| 阶段 | 锁 | 动作 |
|---|---|---|
| A | 持有设备锁 | 封板、流式验封签链/末段/归属/批准代、登记提交窗口 |
| B | **锁外** | Barrier 挂钩、流式拷贝、临时文件 fsync、原子改名（撤销可在此抢先落日志） |
| C | 重持设备锁 | 复核权限；通过则写清单/目录承诺/索引/根承诺/commit 日志并释放暂存；失败则撤下公开文件并 abort |

阶段 B 在设备锁外，配合 `threading.Barrier` 让「撤销抢先」成为确定时序而非靠
`sleep` 碰运气。阶段 C 必须复核批准代，撤销成功的批次即便 pack 已拷贝也会被撤下、
中止，绝不写索引。

## 容量、释放余额与历史水位（ledger.py）

- 每设备日志按代 `approve` 容量；`revoke` 只置撤销标志，持有额由随后的 `abort`
  事件释放（避免重复扣减成负数）。
- `held_bytes`：当前暂存尚持有的压缩字节；`releasable_balance = max(0, 容量 - held)`。
- `watermark_bytes`：历史持有峰值，只增不减；每个变更事件后写检查点。
- 内存状态随日志事件增量维护，避免按分段重放导致 O(n²)；权威事实仍只在磁盘日志，
  检查器不认内存缓存。

## 崩溃恢复（打开即对账）

- `public/<batch>` 有 pack 但缺清单/索引（回执丢失）：重算目录承诺、补清单、
  补 commit 日志、清对应暂存，索引与根承诺整体重建。
- `staging` 中撤销代、失效代、封签损坏、或缺末段的未完成批次：恢复即中止，不公开。
- `tmp/` 残留直接清除；所有多文件写走「同目录临时文件 + fsync + os.replace + 目录落盘」。
- Windows 目录落盘经 `CreateFileW(FILE_FLAG_BACKUP_SEMANTICS)` + `FlushFileBuffers`，
  优先用写访问打开；若会话策略对目录句柄返回 `ERROR_ACCESS_DENIED`，目录刷缓冲降级为
  尽力而为（文件内容 fsync 与原子改名仍保证主要持久性），其它错误照常抛出。

## 独立检查器（checker.py）

不导入 `cage`/`ledger`，自带与日志同语义的独立状态机，所有结论重新打开文件计算：

1. **公开字节**：每个公开 pack 重新验封签链，重算 pack 摘要、清单、目录承诺，
   并与索引条目、`root.json` 逐条对账；
2. **释放余额**：独立重放日志算持有/容量，并与 `staging/` 目录实际字节交叉核对；
3. **历史水位**：水位检查点单调且不低于按事件重放出的实际持有峰值。

任一不变量失败即以退出码 1 报告具体批次/设备。

## 内存核算口径（test_memory.py）

用 `tracemalloc` 核算 Python 解释器内工作内存（非 RSS、非磁盘），四阶段给账：
压缩输入帧总量、暂存水位、索引对象/索引文件、中断重开后尚持有的工作内存。
硬断言全程峰值 `< 8 MiB`，且中断租户被清理后无关租户仍能完整推进并公开。
落盘/fsync 语义在 `test_threads.py` 的 `durable=True` 路径覆盖，内存测试关闭
fsync 以聚焦工作内存。本机实测（100,000 段、10 设备）：载荷压缩比约 0.11，
稳态 tracemalloc 峰值约 0.70 MiB，中断重开恢复峰值约 2.54 MiB，均显著低于 8 MiB。

## 容量与去重口径

- 容量按设备**全部进行中批次合计**的暂存字节核算，而非单批次；交错开多批也不会超签批。
- 重投去重键是 `(批准代, 序号, 载荷摘要, 末段标志)`，与链上 frame 摘要解耦——
  重投时上一摘要上下文可能已变，但同一逻辑分段仍被识别为 duplicate。
- 批次名强制以 `<device>#` 开头，活动批次同时带租户/设备标签，杜绝跨租户串状态。
- 已写末段并封板的批次拒绝续写；同批次重复 stage 按差额计入，绝不全额重复累加持有。
